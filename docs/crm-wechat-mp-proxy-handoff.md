# CRM 服务器公众号固定出口接入说明

更新日期：2026-10-23\
执行人员：CRM 后端开发、CRM 部署维护人员、公众号管理员\
目标：让 CRM 的公众号 API 请求统一通过已部署的固定出口，解决动态出网 IP 导致的微信白名单问题。

本文可直接交给 CRM 维护人员执行。**文档不含真实代理密码、公众号 AppSecret、access_token 或服务器私钥；这些信息另走受控密钥渠道。**

## 一、CRM 维护人员需要完成的事

1. 从中转服务器管理员处安全领取代理环境配置文件和 `check.mjs` 验收工具。
2. 在正式 CRM 后端环境新增 `WECHAT_MP_PROXY_URL`，保留原有其他配置。
3. 核对获取 token、查询用户资料、客服回复和健康检查都使用同一个公众号代理请求封装。
4. 在 CRM 实际运行环境执行代理验收，确认 8 项全部通过。
5. 按 CRM 原有发布方式加载配置，只重启对应 CRM 服务。
6. 由公众号管理员核对 API IP 白名单，再通过正式 CRM 强制刷新 token、查询测试用户资料并验证受控客服回复。
7. 在受控测试环境或维护窗口验证代理故障不会回退动态 IP 直连，完成后恢复并复验。

**不需要迁移 CRM 或数据库，不需要在 CRM 服务器安装 Squid/stunnel，不需要修改公众号消息接收 URL。**

## 三、安全领取接入资料

CRM 维护人员只需要以下两项，不需要服务器 SSH 私钥或 TLS 私钥：

| 资料 | 领取方式与用途 |
| --- | --- |
| 代理环境配置 | 由中转管理员从中转服务器 `/etc/wechat-mp-proxy/crm.env` 安全交付；文件含真实代理密码 |
| 验收工具 `check.mjs` | 来自部署包 `ops/wechat-mp-proxy/check.mjs`，是无第三方依赖的 Node.js 运维工具 |

配置文件通过可信 SFTP、密钥管理系统或其他受控渠道交接。不要通过普通聊天、工单正文、Git、截图或日志传递。文件应仅允许负责部署的账号和必要的 CRM 运行账号读取，禁止放进静态网站目录或前端构建产物。

建议将凭据和公开工具分开存放。后续命令使用如下**示例路径，执行前换成 CRM 的实际路径**：

```text
/opt/crm-secrets/wechat-mp-proxy.env   # 受保护的凭据文件
/opt/crm-ops/check.mjs                # 公开验收工具
```

不要直接覆盖 CRM 整个 `.env`，也不要递归修改现有项目目录权限。备份原部署配置时同样要限制权限。

## 四、配置正式 CRM 环境

### 4.1 新增公众号专用变量

在 CRM 真正运行的后端服务环境中设置：

```dotenv
WECHAT_MP_PROXY_URL=https://mp_crm:REPLACE_WITH_PROXY_PASSWORD@shroom.jq-industries.com:18443
```

这是脱敏格式，**不能直接使用占位密码**。实际接入应安全导入领取的完整配置行，而不是重新手写密码。

当前自动生成的密码使用 URL 安全字符，可以直接使用交付的完整 URL。以后手动轮换含特殊字符的密码时，用户名、密码要分别进行 URL 百分号编码，不能把整个 URL 一起编码，也不要对已编码密码再次编码。

保持以下边界：

- 不修改企业微信通道的 `WECHAT_PROXY_URL`。
- 不用全局 `HTTP_PROXY` 或 `HTTPS_PROXY` 代替这个公众号专用变量。
- 不设置前端 `VITE_`、`NEXT_PUBLIC_` 等公开环境变量。
- 不替换 CRM 已有的数据库、JWT、公众号 AppID/AppSecret、Token 或 EncodingAESKey。
- 不把微信 API 地址改成中转地址，也不把代理 URL 加上 `/relay` 或其他业务路径。

### 4.2 确认配置进入运行进程

按 CRM 现有的 systemd、PM2、容器或托管平台流程注入配置。只把文件复制到服务器或修改交互式终端环境，不等于正式 CRM 进程已经收到变量。

如果 CRM 只在启动时读取环境，必须重新加载配置并重启对应 CRM 服务；若是多副本部署，所有处理公众号请求和后台任务的副本都要一致更新。不要重启全部 PM2 应用、整台服务器或其他项目。

维护人员应确认实际进程拿到的代理协议是 `https:`、主机是 `shroom.jq-industries.com`、端口是 `18443`，且认证字段存在。**只记录这些非敏感字段，不打印完整 URL、环境文件或完整环境变量列表。**

## 五、核对 CRM 公众号请求代码

根据 CRM 原交接说明，应已有 `server/mpHttp.ts` 和 `WECHAT_MP_PROXY_URL` 支持。但本次中转部署没有获得 CRM 代码访问权限，以下事项必须由 CRM 开发者核对正式分支，不能假定已经实现。

| 核对项 | 必须达到的行为 |
| --- | --- |
| 代理实现 | 使用兼容 HTTPS CONNECT 的客户端，例如 CRM 现有 `HttpsProxyAgent` |
| 获取或刷新 token | 走同一公众号代理封装，不能仍直连微信 |
| 用户资料查询 | 走同一封装，不能在其他模块单独发直连请求 |
| 客服回复、公众号健康检查 | 走同一封装；消息接收回调不迁移 |
| 目标限制 | 只访问 `https://api.weixin.qq.com`；其他域名不应改为直接访问绕开限制 |
| 重定向 | 不跟随跳转到其他主机 |
| 超时 | 保留原交接说明中的单次请求 12 秒超时，核对实际实现 |
| 代理配置存在但连接失败 | 返回明确错误，不自动改用直连 |
| 配置缺失 | 原说明称当前可能直连，正式切换须主动检查变量存在，不能把漏配当成已经阻断 |
| 凭据和日志 | 不输出代理 URL、认证头、AppSecret、token、客户消息正文或携带这些信息的完整错误对象 |

微信请求地址继续使用原地址，例如 `https://api.weixin.qq.com/cgi-bin/...`。由代理 Agent 建立隧道，中转不解密微信 HTTPS，不需要从 CRM 接收公众号 AppSecret。

仅配置变量不会自动改变任意 HTTP 客户端的行为；必须确认实际请求代码使用了代理。`HttpsProxyAgent` 的 CONNECT 机制参见[官方说明](https://raw.githubusercontent.com/TooTallNate/proxy-agents/main/packages/https-proxy-agent/README.md)。

## 六、先在 CRM 环境做无公众号密钥验收

在 **CRM 所在主机、容器或等价网络环境**执行，不要用开发电脑测试成功替代正式环境验证。运行账号要能够读取凭据文件。

验收工具建议使用 Node.js 22+。如 CRM 运行时不同，先核对工具兼容性或使用批准的运维环境，不为运行探测而直接升级生产 CRM。

下面以 Linux 和上文示例路径为例：

```bash
env -u WECHAT_MP_PROXY_URL node \
  --env-file=/opt/crm-secrets/wechat-mp-proxy.env \
  /opt/crm-ops/check.mjs
```

`env -u` 只清除这个探测子进程继承的旧值，让指定文件生效，不修改正在运行的 CRM。Node 的已有环境变量优先于 `--env-file` 中同名变量，所以要避免误测旧代理；文件必须是管理员交付的可信文件。[Node.js 官方说明](https://nodejs.org/download/release/v22.23.0/docs/api/cli.html#--env-filefile)

期望输出的 8 项结果为：

```text
PASS missing-auth
PASS wrong-auth
PASS other-domain
PASS domain-suffix
PASS literal-ip
PASS wrong-port
PASS plain-http
PASS wechat-tls
```

程序正常退出，退出码为 0；最后还会提示公众号白名单和实际出口仍需 CRM 验证。任何一项 FAIL 都不能宣布接入成功。

该工具不会获取 token 或给客户发消息。它验证的内容是：

- 无认证和错密码得到代理 407。
- 其他域名、伪造域名后缀、IP 目标、非 443 端口和普通 HTTP 得到 403。
- 正确认证建立到微信的 CONNECT 隧道，并验证微信 TLS 证书；代理外层 TLS 同样验证证书链和域名。

不使用 `curl --proxy-insecure`、`rejectUnauthorized: false` 或 `NODE_TLS_REJECT_UNAUTHORIZED=0` 处理证书问题。

## 七、正式公众号业务联调

### 7.1 核对公众号白名单

由公众号管理员在对应公众号的 **API IP 白名单**中添加已核实的中转固定出网 IPv4，填写纯 IP，不带协议、端口或路径。

若运维确认该实例固定 EIP 就是实际微信出口，则填写：

```text
39.105.83.246
```

保留其他仍在使用的合法白名单条目。不要填写中转域名、微信服务器 IP 或 CRM 当前的临时出网 IP 来代替中转出口。没有核实出口或白名单时，代理 8 项测试通过也不能作为公众号联调成功的证据。

### 7.2 重启 CRM 并强制刷新 token

按原发布流程使配置进入正式服务后，使用 CRM 已有健康检查或运维入口执行 **强制刷新**，不能只读旧 token 缓存。

原 CRM 说明提到 `getMpAccessToken({ forceRefresh: true })`，请开发者核实当前代码是否仍支持，不能把这个函数名当作已经存在的 HTTP URL。沿用 CRM 现有的 token 缓存和并发刷新机制，避免多个脚本同时反复刷新。

验收需要同时满足：微信返回成功、没有 `40164 / invalid ip`，并且可从脱敏观测或代码/网络核对中确认请求确实走了新代理。记录操作时间、结果与脱敏错误码，不记录真实 token、AppSecret 或完整请求 URL。

### 7.3 查询测试用户资料

使用已获授权、符合公众号接口条件的测试用户，验证用户资料请求也经过代理。获取 token 成功而用户资料仍直连，不算完成。

### 7.4 验证受控客服回复

由业务负责人指定允许测试的会话和消息内容，确认满足微信接口权限及会话限制后测试。检查 CRM 中消息发送状态和测试账号实际收信情况，避免把 HTTP 200 当成业务成功。

未确认测试会话前不要向真实客户群发、补发欢迎语或自动重试客服消息。切换过程不修改公众号消息接收 URL、Token、EncodingAESKey 或 CRM 原消息处理链路。

## 八、验证故障不会恢复动态 IP 直连

先安排受控测试实例或维护窗口，明确受影响业务和恢复负责人。不要为演练直接停止全体 CRM 共用的中转服务。

1. 在测试实例的受保护环境中使用错误代理认证，或阻断该测试实例到代理的连接。
2. 触发强制刷新 token 或一个确认不会命中缓存的请求。
3. 确认 CRM 返回代理错误；结合代码检查和连接观测，确认没有绕过代理直连微信。
4. 恢复原受保护配置并重新加载，重复正常代理与公众号健康检查。

一次旧缓存命中不能证明故障不回退。正式服务不要用清空 `WECHAT_MP_PROXY_URL` 当作自动恢复手段；原说明称变量为空时可能直连，这正是本次要避免的动态出口。

## 九、常见问题与处理

| 现象 | 优先核对 | 不应采取的做法 |
| --- | --- | --- |
| 连接 18443 超时 | CRM 出站策略、DNS、代理安全组/主机规则、代理服务状态 | 改用公网明文 3128 |
| 代理 407 | 是否完整导入凭据、是否用错密码、保留字符编码是否正确 | 关闭认证或把密码打印到日志 |
| 代理 403 | 目标是否精确为微信 API 域名和 443、是否 CONNECT、是否达到连接上限 | 扩大为通用互联网代理或失败后直连 |
| TLS 证书错误 | 域名、系统时间、信任链、代理证书副本是否已更新 | 跳过证书校验 |
| 微信 40164 | 是否全部 API 都经代理、实际出网 IPv4 与公众号白名单是否一致、是否误用缓存/旧配置 | 把域名、微信 IP 或端口填写进 IP 白名单 |
| 探测通过但 token 获取失败 | 正式进程是否加载变量、AppID/AppSecret、公众号权限、微信业务错误码 | 宣称网络正常就等于公众号恢复 |
| 重启后配置丢失 | 变量是否进入持久服务配置、所有副本/后台任务是否更新 | 只在临时 SSH shell 里 export |

错误对象可能包含 HTTP 客户端配置、认证或带 token 的 URL。对外交接只提供脱敏错误码、代理非敏感主机/端口和时间，不转储完整异常对象。

## 十、回退与后续维护

出现问题先暂停新增流量、保存脱敏错误并联系中转管理员，优先修复固定出口。确需回退时，由管理员明确确认原配置和对应白名单出口仍可用，再恢复之前的受保护配置并按 CRM 原流程发布、复验；不要默认清空变量就能稳定恢复。

责任分工如下：

| 负责人 | 持续维护事项 |
| --- | --- |
| CRM 维护人员 | 保持配置持久化、所有公众号请求统一走代理、超时/重试与脱敏日志、故障不直连 |
| 公众号管理员 | 白名单与接口权限、测试会话确认 |
| 中转管理员 | 代理服务、入口与固定 EIP/NAT、密码轮换、容量、TLS 证书及续期同步 |

中转目前使用原站证书的专用副本，证书到期为 `2027-01-13 23:59:59 UTC`，即北京时间 `2027-01-14 07:59:59`。原站证书续期不会自动更新代理副本，续期同步尚未接入自动 hook，需中转管理员落实。CRM 不需要接收这份私钥。

密码轮换需要中转端和 CRM 配置配套更新，并从 CRM 环境重新验收。不要把临时清空代理变量作为轮换过渡方案。
