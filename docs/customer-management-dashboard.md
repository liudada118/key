# 客户、合同与使用看板

更新日期：2026-10-16

## 页面结构

保留客户管理、合同管理、客户使用分析三个入口，默认展示指标和图表；管理操作和完整表格放在明细视图。事业部、搜索或使用时间范围作为共享筛选条件，图表与指标可以下钻到明细。

## 客户看板

| 指标 | 定义 | 数据来源 | 查看明细 |
| --- | --- | --- | --- |
| 客户总数 | 当前归属权限、搜索和事业部范围内的全部客户档案，含禁用客户 | 本地客户库 | 全部客户 |
| 已关联合同 | 至少关联一份当前账号可见飞书合同的客户数 | 客户名称归一化匹配飞书合同 | 合同覆盖=已关联 |
| 未关联合同 | 没有关联到可见合同的客户数，不等于该客户实际没有合同 | 同上 | 合同覆盖=未关联 |
| 部门待完善 | 至少一份关联可见合同尚未解析出事业部的客户数 | 飞书事业部或发起人对应系统账号部门 | 合同覆盖=部门待完善 |
| 合同覆盖率 | 已关联合同客户数 / 客户总数；分母为0时不计算 | 同上 | 覆盖分布条形图 |
| 事业部客户分布 | 每个事业部分别按客户档案去重；跨部门客户可在多个部门出现 | 当前可见合同汇总 | 事业部筛选 |

客户指标与分布不受明细分页影响；事业部分布展示前8项。明细可以继续叠加客户状态、搜索和分页。飞书读取失败时客户总数仍可用，合同覆盖指标为“暂不可用”，不以0或无合同替代。

## 合同看板

| 指标 | 定义 | 查看明细 |
| --- | --- | --- |
| 合同总数 | 当前账号和事业部可见的全部去重飞书合同 | 全部状态、全部开钥进度 |
| 生效中合同 | 飞书映射后状态为ACTIVE的合同数 | 状态=生效中 |
| 已开钥合同 | 已有至少一条关联在线密钥历史生成记录的合同数 | 在线开钥进度=已生成 |
| 待开钥合同 | 状态为ACTIVE且没有在线密钥生成记录的合同数 | 状态=生效中，进度=未生成 |
| 合同状态分布 | 草稿、生效中、过期、终止合同数 | 点击状态进入对应明细 |
| 事业部合同分布 | 各部门的合同总数与已开钥合同数 | 点击已匹配部门进入明细 |

沿用现有在线合同开钥查询口径：不含离线密钥，包含已吊销在线密钥的历史生成记录，不表示当前有效授权。没有可靠金额或收入数据，因此不展示营收、回款或虚构环比。未提供有效期的合同不推断即将到期。

## 使用看板

保留现有已确认业务使用、监测时长、安装数和异常影响汇总。新增按日趋势与前8项功能/客户排行：

- 趋势可以切换每日业务使用客户/来源数、监测分钟数或错误上报次数，不混合不同单位的纵轴。
- 业务功能按使用客户/来源数排序；客户按监测时长优先、已确认使用次数次序排序。没有监测时长时使用次数展示仍有意义。
- 点击功能进入“哪些客户使用该功能”；点击客户进入“该客户使用哪些功能”，之后仍可查看系统、操作记录及错误上下文。
- 全部聚合沿用现有历史归属快照、操作去重、环境、版本、功能和客户过滤规则。仅启用中的超级管理员可读。
- 时间为UTC，范围最多93天；空日期填0代表当日未观测到对应上报，不表示实际未使用。完全没有上报时展示空状态，不画伪造趋势。
- 可展开每日数值用于键盘和读屏访问。诊断、入口展示或失败事件不被当作已确认的业务使用。

## 关注项

部门待完善大于0时，检查发起人姓名及本环境人员部门配置。待开钥合同不自动发送提醒或生成密钥，应按业务需要处理。异常影响客户大于0时可进入既有异常排查视图。没有设定虚构的业务目标，也不新增自动通知。

## 技术边界

- 新增 `customers.dashboard`、`contracts.dashboard` 和 `usage.dashboard` 只读查询；响应禁止缓存。
- 客户看板只读取全范围的ID、名称、启用状态，联系信息仅参与现有搜索条件，不返回给图表。
- 客户合同覆盖和合同开钥筛选在服务器计数、分页前执行；来源失败时不能静默返回全部明细。
- 无新增依赖、环境变量或数据库迁移，不写飞书、不修改账号权限，不向业务库插入测试数据。
